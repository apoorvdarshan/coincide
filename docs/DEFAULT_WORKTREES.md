# First-send workspace defaults

New native project drafts capture the resolved New thread workspace setting when authored: project override, app default, `t3.json`, then Local. The origin preference (`newWorktreesStartFromOrigin`) resolves from the project override, then the app preference (default true), and is captured with that draft. A later settings change does not reinterpret existing, imported, active, or historical conversations. As in the pinned T3 implementation, the first draft in a direct child of the managed-project root uses Local when Worktree came only from the global environment preference; an explicit repository/project override still wins.

For a Git worktree choice, the saved intent belongs to the original thread ID/birth and project ID/birth/exact path. It retains the actual selected local branch and descriptor-bound source/repository/Git-administration identities. A folder positively reported by Git as not a repository uses Local. An inaccessible, detached or unborn Git checkout cannot silently become a base-checkout turn; choosing Local remains explicit.

On explicit Send, one durable command admits the original native input and the managed worktree preparation together. The input keeps its original command/run UUID and native attachment references, model, permissions, runtime and checkpoint policy. A separate deterministic preparation ID owns the folder and branch, avoiding collisions with the provider-start effect. No provider input is sent until the ordinary checkout, submodule and setup-review gates permit it. The input does not appear as an authored provider turn while it is waiting for workspace readiness.

When origin mode is enabled, preparation uses the captured branch's actual configured upstream remote and merge ref. If there is no applicable upstream, an actually configured `origin` may provide that same branch. Without either configured remote, the local branch is used. No `origin/main` or other default branch is invented. Fetching a missing remote branch fails even if a stale tracking ref remains. Fetch errors leave the original input queued; they do not send it in the source checkout.

Use This Checkout durably removes the pending worktree intent without consuming the draft or attachments. Explicit Choose Worktree uses the existing reviewed preparation and clears the default intent only on successful admission. Failed/cancelled automatic preparations retain the original request, folder, branch and queued input. Explicit Retry first inspects a saved plan, then reuses that same request; it never deletes unproven partial files or creates another managed folder. Ordinary queue pause/recovery rules still apply. Reopening the app or looking up an original accepted command does not replay its input.

## Ownership and verification

Scratch/No project folders never receive a default-worktree intent. Both the project and conversation scratch markers are checked when capturing a draft and admitting its first input; scratch ownership grants are never copied into Git worktree authority.

The new immutable intent and automatic-base records are reference backed so large Git proof values do not enlarge every `CodingThread`, worktree request and reducer frame.

Focused test source (`defaultWorktree` filter) covers Core reducers, real private Git repositories and native store behavior, including persistent per-project origin overrides. It covers original-input/reference capture, stale ownership, real private local/bare Git upstream fetching and dirty/index preservation, stale tracking-ref failure, native Engine/SQLite setup approval, original receipt after restart, cancel/retry without another folder, physical source/Git-pointer replacement, native draft capture, persistent Local override, and the pinned managed-first-draft exception. Providers are private in-memory peers; no real models, auth, SSH or network are used. Installed-provider, SSH and interactive native-window acceptance remain separate from these offline fixtures.

Remote drafts and the remote composer do not gain workspace-default settings or first-send bootstrap through this native adapter. MCP thread creation/project inheritance is unchanged; scoped MCP calls cannot dispatch or retry the native-only default-worktree command. A future remote/MCP adapter must preserve its original command receipt and captured project/provider/permission authority. Detached and unborn repositories currently require an explicit Local/custom choice; the automatic new-worktree draft cannot be captured until a committed local branch is available.
