# Native Claude conversation history

Run History now connects Claude's native Swift transcript reader and exact-file
fork store to reviewed Fork After Run and Rewind Before Run controls. Rewind
selects the next conversation context; it does not truncate native history or
send a prompt. Installed Claude Code 2.1.304 passes a four-turn native
fork/deferred-rewind acceptance check. Broader compatibility, hosted GUI
acceptance and complete T3 parity remain unfinished.

## Reference and evidence

The transcript algorithms are pinned to the official
[`@anthropic-ai/claude-agent-sdk` 0.3.276 package](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/0.3.276),
with conversation-control behavior taken from
[T3 Code `680152e27b2a961686389ca69a1557cbb2c55f08`](https://github.com/pingdotgg/t3code/tree/680152e27b2a961686389ca69a1557cbb2c55f08).
Its `sdk.mjs` SHA-256 is
`b1607967e0dfb39a0db45f143d3b57c7a85f2f6eaa77d6bee7d8184a9830a9f3`.
The package declares Claude Code 2.1.276; this is source metadata, not an
observation of the user's installed CLI. The installed executable was separately
read as 2.1.304. Its help advertises `--session-id` and `--replay-user-messages`;
the hidden `--resume-session-at` behavior is separately verified by the opt-in
four-turn installed test, including generated-marker context recall, exact
native branch proof and SQLite restart. This observation applies to that
installed version and case; the pinned transform and offline fixtures alone do
not establish compatibility with other versions or native formats.

Seven committed synthetic oracle cases were generated by the original SDK's
`getSessionMessages` and `forkSession` in a private temporary configuration/home.
The generator removes inherited environment variables and rejects subprocesses
and network connections; all cases completed with zero prohibited calls. Neither
an installed Claude process, authentication nor a model turn was used. The normal
Swift tests compare exact reader output and normalized fork payload/order against
those independent results. They require neither Node nor the SDK.

To reproduce the optional development oracle, obtain that exact official package
and run `node script/generate_claude_history_oracle.mjs /path/to/extracted/package`.
The generator checks its source hash, verifies unchanged source files and removes
its private scratch directory. Its fixture is synthetic, not captured user data.

## Pure transcript behavior

`ClaudeTranscript` keeps the raw JSONL inventory separately from the SDK's selected
parent/tool chain and projected user/assistant messages. It stitches both native
compaction forms, restores parallel assistant/tool-result branches and promotes
eligible settled queued-command attachments using their distinct source UUIDs.
The default reader's precompaction skip applies only above 5,242,880 source bytes;
raw fork input remains complete. A runtime disabling that native optimization
needs a separate compatibility profile before using this evidence.

Fork cuts are inclusive. Native UUID allocation, progress-parent bypass,
`forkedFrom` lineage, native content, compaction fields, inherited replacement
payloads, history flags and supported metadata follow the pinned transform.
Progress UUIDs remain in the allocation map even though progress rows are omitted.
The last projected reader UUID can precede a structured-output/tool tail; it does
not prove the kept turn's final native resume boundary. Pure data cannot observe
the SDK's optional title sidecar; an explicit verified title can be supplied.

Mutation evidence is intentionally stricter than the SDK's tolerant display
reader: malformed JSON/UTF-8, duplicate UUID updates, case-only UUID aliases,
mixed sessions and cycles are refused. Inventories are bounded to 16 MiB,
20,000 records and 4 MiB per line, with bounded graph work. Shared progress
ancestors are memoized. Unknown metadata is retained in the raw inventory;
collection and omission follow the pinned transform. This alone does not prove
compatibility with an unknown future native format.

## Exact-file publication and inspection

`ClaudeTranscriptStore` requires explicit physical configuration/workspace roots.
It derives the SDK's NFC/UTF-16 project key and optional validated project-name
override, consulting at most that override and its legacy key. It does not scan
other projects/accounts or launch Git to discover worktrees. Missing, ambiguous
or unsupported relocated/worktree locations are refused.

Reads descend through anchored directory descriptors, reject symlinks, special
files and multiply linked/unowned files, and verify name/inode/stat identity and
bounded bytes. A source revision includes its SHA-256. `prepareFork` returns
transient target bytes plus a Codable reservation containing exact source/target
locations, source revision, expected target digest/size and UUID/head mapping.
The Engine journals that reservation in the dispatched history operation before
the service is allowed to publish. Preparing or cancelling a review writes no
native transcript.

Publication rechecks the source, exclusively creates the reserved UUID file with
mode 0600, fsyncs the file and parent, then verifies source and target again.
This is deliberately stronger than the pinned SDK's local `w` publication. An
uncertain outcome preserves its exact destination. `inspect` only reads that
reserved target and revalidates the complete semantic copy against the source;
a matching digest alone is insufficient. It never overwrites, deletes, guesses
a recent file or repeats publication. These observations do not provide native
compare-and-swap or exclusion of arbitrary external writers.

## Reviewed native workflow

New runs capture the exact launcher, physical Claude configuration/workspace,
registered workspace spelling, project-name override and precompaction profile.
They also retain whether the configuration came from the default home or an
explicit `CLAUDE_CONFIG_DIR`, including the original environment spelling.
Those choices can select different CLI credential namespaces even when their
transcripts resolve to the same physical directory. Default launches preserve
the captured `HOME` and leave `CLAUDE_CONFIG_DIR` absent; explicit launches
restore the exact override. Before starting a process, both must still resolve
to the captured physical root. This does not read or migrate credentials.
Original input UUIDs derive prospectively from the persisted run; steering UUIDs
derive from the persisted client message ID. Non-replayed root envelope UUIDs and
terminal ownership are recorded separately from API message IDs, child events and
legacy `turnIDs`. A history review must match those owners to the actual selected
native input/assistant records. Old or incomplete histories remain gated; text,
timestamps and weak adapter references are never upgraded into native proof.

Fork After Run uses the selected completed run's exact root-assistant UUID as an
inclusive cut. Review first drains the idle source owner so its native metadata
flush is included in the reviewed revision. Acceptance reserves a distinct target UUID in the
durable operation, publishes only that native file and verifies the complete
copy. The new conversation uses the selected run's captured settings and the
verified remapped inherited head. It starts with a blank composer and sends no
prompt; the source and its draft are preserved. An uncertain fork holds both
source and reserved destination until read-only Inspect proves the exact target
ready or not started. Partial/foreign targets are preserved and never republished.

Rewind Before Run follows T3's inclusive root-assistant context selection. It
keeps the native session and raw transcript intact and saves a deferred cursor
for the next explicit user submission. Before the first local run, a verified
fork restores its inherited head; a genuinely fresh conversation reserves a new
session instead of resuming a nonexistent file. Pending re-reviews use the
effective selected prefix while retaining the unchanged raw source revision.
No `resumeDropsTurn` launch mode or native file-rewind call is enabled.

Exactly one explicit successor run captures the pending selection. It is not
copied into every queued follow-up. A matching observed successful successor
consumes it; failed or uncertain consumption remains held for read-only Inspect
without repeating the prompt or silently falling back to another context. The
native banner distinguishes a selected context from a completed model response.

Ownership checks cover registered, active, queued, metadata and closing actors
that address the same physical configuration/native session, including launcher
and workspace aliases. Current draft, pin and title edits remain separate from
the history transition. The native review offers Cancel, Revert and Keep Changes,
or the separately reviewed Revert Files Too path. Workspace restoration requires
its exact checkpoint and explicit loss warning; it is never implied by native
rewind. Prompt recall appends the original input to the latest composer exactly
once only after every selected stage succeeds. Original run IDs and removed
audit rows remain intact across native reference changes and restart.

## Verification still required

The current implementation includes synthetic protocol, transcript, filesystem,
reducer, Engine and native-view fixtures. Results for the current batch belong in
[VALIDATION.md](VALIDATION.md); this document does not claim they have all passed.
Installed 2.1.304 model/fork/deferred-resume acceptance passed in the generated
four-turn case; interactive hosted history UI acceptance and broader native
compatibility remain separate gates. Unsupported relocated/worktree lookup and
unknown native formats are refused. This work adds no managed Claude installer,
provider authentication migration, account UI, or portable-context substitute for
native history.
