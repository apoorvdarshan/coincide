# Native Claude history primitives

Claude's native Swift transcript reader, fork transformation and exact-file store
are implemented as Core primitives. They do **not yet enable** Claude history
actions in Run History. Complete Claude fork/rewind integration and complete T3
parity remain unfinished.

## Reference and evidence

The reference is the official
[`@anthropic-ai/claude-agent-sdk` 0.3.276 package](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/0.3.276),
pinned by [T3 Code `680152e27b2a961686389ca69a1557cbb2c55f08`](https://github.com/pingdotgg/t3code/tree/680152e27b2a961686389ca69a1557cbb2c55f08).
Its `sdk.mjs` SHA-256 is
`b1607967e0dfb39a0db45f143d3b57c7a85f2f6eaa77d6bee7d8184a9830a9f3`.
The package declares Claude Code 2.1.276; this is source metadata, not an
observation of the user's installed CLI.

Seven committed synthetic oracle cases were generated by the original SDK's
`getSessionMessages` and `forkSession` in a private temporary configuration/home.
The generator removes inherited environment variables and rejects subprocesses
and network connections; all cases completed with zero prohibited calls. Neither
an installed Claude process, authentication nor a model turn was used. The normal
Swift tests compare exact reader output and normalized fork payload/order against
those independent results. They require neither Node nor the SDK.

To reproduce the optional development oracle, obtain that exact official package
and run `node script/generate_claude_history_oracle.mjs /path/to/extracted/package`.
The generator checks its source hash, verifies unchanged source files and removes
its private scratch directory. Its fixture is synthetic, not captured user data.

## Pure transcript behavior

`ClaudeTranscript` keeps the raw JSONL inventory separately from the SDK's selected
parent/tool chain and projected user/assistant messages. It stitches both native
compaction forms, restores parallel assistant/tool-result branches and promotes
eligible settled queued-command attachments using their distinct source UUIDs.
The default reader's precompaction skip applies only above 5,242,880 source bytes;
raw fork input remains complete. A runtime disabling that native optimization
needs a separate compatibility profile before using this evidence.

Fork cuts are inclusive. Native UUID allocation, progress-parent bypass,
`forkedFrom` lineage, native content, compaction fields, inherited replacement
payloads, history flags and supported metadata follow the pinned transform.
Progress UUIDs remain in the allocation map even though progress rows are omitted.
The last projected reader UUID can precede a structured-output/tool tail; it does
not prove the kept turn's final native resume boundary. Pure data cannot observe
the SDK's optional title sidecar; an explicit verified title can be supplied.

Mutation evidence is intentionally stricter than the SDK's tolerant display
reader: malformed JSON/UTF-8, duplicate UUID updates, case-only UUID aliases,
mixed sessions and cycles are refused. Inventories are bounded to 16 MiB,
20,000 records and 4 MiB per line, with bounded graph work. Shared progress
ancestors are memoized. Unknown metadata is retained in the raw inventory;
collection and omission follow the pinned transform. This alone does not prove
compatibility with an unknown future native format.

## Exact-file publication and inspection

`ClaudeTranscriptStore` requires explicit physical configuration/workspace roots.
It derives the SDK's NFC/UTF-16 project key and optional validated project-name
override, consulting at most that override and its legacy key. It does not scan
other projects/accounts or launch Git to discover worktrees. Missing, ambiguous
or unsupported relocated/worktree locations are refused.

Reads descend through anchored directory descriptors, reject symlinks, special
files and multiply linked/unowned files, and verify name/inode/stat identity and
bounded bytes. A source revision includes its SHA-256. `prepareFork` returns
transient target bytes plus a Codable reservation containing exact source/target
locations, source revision, expected target digest/size and UUID/head mapping.
The caller must journal that reservation before calling `publish`; this primitive
does not write the workspace database itself.

Publication rechecks the source, exclusively creates the reserved UUID file with
mode 0600, fsyncs the file and parent, then verifies source and target again.
This is deliberately stronger than the pinned SDK's local `w` publication. An
uncertain outcome preserves its exact destination. `inspect` only reads that
reserved target and revalidates the complete semantic copy against the source;
a matching digest alone is insufficient. It never overwrites, deletes, guesses
a recent file or repeats publication. These observations do not provide native
compare-and-swap or exclusion of arbitrary external writers.

## Integration still required

Claude history controls remain gated until the following work is connected:

- Capture exact runtime/configuration/project-key/profile and prospective original
  and steering input UUIDs before submission, plus owned non-replayed root
  assistant/tail evidence. Legacy `turnIDs` must remain uninterpreted.
- Close/drain the exact source runtime, durably reserve fork publication, verify
  and adopt its remapped inherited head, and recover exact uncertain destinations.
- Implement T3's same-session deferred rewind selection. The next explicit send
  uses the selected native cursor; accepting rewind sends no prompt and does not
  truncate the original transcript or call native file rewind.
- Preserve inherited fork context before the first local run; a fresh reset uses
  a reserved session ID with fresh-session launch, rather than resume of a
  nonexistent transcript.
- Journal selection consumption by its exact successor run so captured queued
  follow-ups cannot accidentally reapply a completed rewind after runtime restart.
  Preserve uncertain delivery without replay or silent context fallback.
- Integrate scope ownership, reviewed Git-file restoration, prompt recall and the
  native review/recovery UI, then verify installed CLI/version behavior and full
  end-to-end acceptance independently of these offline primitives.
