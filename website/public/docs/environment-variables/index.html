Environment variables

Coincide starts agents with your login shell’s environment, plus a few variables of its own. This page lists the variables that matter to you: those you can set for Coincide, those your agents and scripts receive, and those Coincide sets for agent accounts.

Updated November 1, 2026

What agents start with

Coincide reads your login shell’s environment once, as a new Terminal window would, and starts every agent with it. It adds the usual install folders to PATH and removes variables that would make an agent think it’s running inside another Claude Code session, for when you start Coincide from one. On each agent’s page in Settings, Environment Variables adds your own on top, for example a custom base URL.

Variables Coincide reads

VariableEffect
COINCIDE_DATA_DIRUse this folder instead of ~/Library/Application Support/Coincide for Coincide’s data, its worktrees and Antigravity’s profile. Meant for testing; see data storage.
COINCIDE_CONTROL_SOCKETRead by the coincide command: the socket to talk to. --socket overrides it.
COINCIDE_THREAD_IDRead by the coincide command: the thread this means.
COINCIDE_AGENT_HOST=1In a Debug build from source, use the background agent host instead of running agents in the app.
CLAUDE_CONFIG_DIR, CODEX_HOMEWhere File › Import CLI Session… looks for Claude Code and Codex histories, when set in Coincide’s own environment.

Variables Coincide gives agents

VariableWhenValue
PATHWhile Command-line control is onGains the folder with the coincide tool inside Coincide.app
COINCIDE_CONTROL_SOCKETWhile Command-line control is onThe socket of the Coincide that started the agent
COINCIDE_THREAD_IDWhile Command-line control is onThe agent’s own thread, so coincide … this works
BW_SESSIONWhen you connected Bitwarden and turned on Let agents use your unlocked password managers in Settings › BrowserBitwarden’s unlocked session, so the agent’s bw can read your vault without unlocking it

Agents already running get BW_SESSION when they next start. Leave that setting off unless you want agents to read any item in your Bitwarden vault without asking.

Variables for your shell and scripts

VariableWhereMeaning
COINCIDE_RESOLVING_ENVIRONMENT=1Your shell’s startup files, while Coincide reads your environmentLets a slow .zshrc skip work Coincide doesn’t need. Agents never see it.
COINCIDE_PROJECT_ROOTProject scripts run from the terminalThe project’s folder
COINCIDE_WORKTREE_PATHProject scripts, when the thread has its own worktreeThe worktree’s folder, for example to copy .env into it
T3CODE_PROJECT_ROOT, T3CODE_WORKTREE_PATHProject scriptsThe same values under T3 Code’s names, so scripts from t3.json work unchanged

Variables Coincide sets for agent accounts

The default account of each agent uses its tool’s own settings. For each account you add, Coincide sets the variable that moves the tool’s sign-in to a folder of that account, or the one that carries its API key. It also clears API-key variables your shell exports for that agent, so the account uses only its own sign-in.

AgentSign-in folderAPI key
Claude CodeCLAUDE_CONFIG_DIRANTHROPIC_API_KEY
CodexCODEX_HOMEOPENAI_API_KEY, saved in that CODEX_HOME with codex login --with-api-key
Cursor—CURSOR_API_KEY
Grok BuildGROK_HOMEXAI_API_KEY
OpenCodeXDG_DATA_HOMEOPENCODE_API_KEY (OpenCode Zen), or ANTHROPIC_API_KEY, OPENAI_API_KEY, OPENROUTER_API_KEY, GOOGLE_GENERATIVE_AI_API_KEY, XAI_API_KEY, GROQ_API_KEY, DEEPSEEK_API_KEY or MISTRAL_API_KEY
Antigravity—GEMINI_API_KEY

Keys come from the Keychain and go only into that agent’s process. More in Accounts and API keys.
