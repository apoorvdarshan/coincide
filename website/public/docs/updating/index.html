Updating Coincide

Coincide updates itself from its GitHub releases. It checks once a day, downloads only when you say so, verifies every byte and installs only when you quit. It never quits or reopens on its own, and it keeps the previous app as a backup.

Updated November 1, 2026

Checking for updates

Choose Coincide › Check for Updates…. Coincide opens Settings › About and asks GitHub’s public Releases API for the latest release. The App Updates section there shows the result, such as “Coincide is up to date.”

Automatic checks are on by default: Coincide looks once a day while it’s open. To turn them off, clear Check for updates daily in Settings › About. A check only asks GitHub which version is newest; it doesn’t download anything, stop agents or quit the app. As with any request, GitHub sees your IP address (see the privacy policy).

Only regular releases count. Coincide offers a release when its version is newer than the one you run; it never offers a downgrade or the same version again.

Downloading and installing

  1. When a newer version is available, click Download Update. Coincide downloads the release’s universal ZIP from GitHub into its own private folder under ~/Library/Caches/com.apoorvdarshan.coincide/Updates and checks its size and SHA-256 checksum against what GitHub publishes. It then checks the app inside: the bundle ID and version must match the release, it must be signed with Developer ID by the same team as the copy you run, and it must pass Gatekeeper. The section then says “The update is verified and ready to install.”
  2. Click Install on Quit. Nothing happens yet: Coincide arms a small signed helper and tells you “The update will install after you quit. Wait for confirmation, then reopen Coincide yourself.” Until you quit, Cancel Installation takes it back.
  3. Quit Coincide as usual. After Coincide has saved everything and exited, the helper verifies the update again from the downloaded archive, puts the new app in place and shows a confirmation.
  4. Open Coincide again yourself.

Show Update Folder reveals the staged download in Finder while it’s ready or armed.

What the installer won’t do

  • It never reads or changes your threads, projects, agent sign-ins or settings, and never asks for an administrator password.
  • It installs only after a normal quit. A crash, a Force Quit, another running copy of Coincide, a failed check or a folder it can’t write to leaves the update uninstalled. Reopening Coincide before the confirmation appears makes the helper refuse, so wait for it.
  • It keeps the old app next to the new one as .Coincide-backup-<ID>.app, a hidden file in the same folder, and never deletes it. If a final check fails, it swaps the old app back.

Old backups stay until you remove them. To find them in /Applications:

ls -a /Applications | grep Coincide-backup

Agents during an update

With Keep agents running when Coincide quits on (Settings › General › Agents), agents work in Coincide’s background agent host, so quitting to update doesn’t stop a running turn. The host runs from its own copy of its files, so replacing Coincide.app doesn’t disturb it, and the new version takes its sessions over when you open it. Agents that run inside the app (with that setting off) stop when you quit, and Coincide asks first. See Background agents.

If you installed with Homebrew

The Homebrew cask marks Coincide as updating itself (auto_updates true), so use the in-app updater as above. A plain brew upgrade skips casks like this; to have Homebrew reinstall the latest release anyway, run:

brew upgrade --cask --greedy coincide

If you installed with npx

Coincide updates itself in the same way. Running the installer again also installs the latest release over your copy, after checking its checksum, signature and notarization; if Coincide is running, it asks before quitting it (or pass --yes):

npx coincide-dev

To install a particular version, name it, as in npx coincide-dev install 0.1.0. npx coincide-dev where prints where Coincide is installed and which version it is.

Builds you made yourself

Only a verified Developer ID build can install updates. A copy you built from source with the default ad-hoc signing can check for updates but shows “Updates can only be installed by a verified Developer ID build.” Download the release instead, or keep building from source (see Build from source).

When something goes wrong, the troubleshooting guide lists each updater message and what to do. What changed in each version is in the changelog.
