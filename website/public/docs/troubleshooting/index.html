Troubleshooting

Most problems come from an agent’s own command-line tool: it isn’t on the path Coincide sees, it isn’t signed in, or it’s too old. The messages below are the ones Coincide shows, with what to do about each.

An agent isn’t found

Message: “Agent is not installed or could not be found on PATH.”

Coincide doesn’t start agents through Terminal, so it reads your login shell’s environment once (as if you opened a new Terminal window) and adds the usual install folders: Homebrew’s, /usr/local/bin, ~/.local/bin, ~/.bun/bin, ~/.npm-global/bin, ~/.cargo/bin, ~/.grok/bin, ~/.opencode/bin and ~/.cursor/bin.

  1. Check the tool runs in a new Terminal window, for example claude --version or cursor-agent --version.
  2. In Settings, open the agent under Providers and click Check Again. Coincide reads your shell’s environment again, so a PATH you just changed counts.
  3. If it’s installed somewhere else, set Custom path under Executable to the program itself. “There’s no executable file at this path.” means the path is wrong or not executable. Leave the field empty to search the PATH again.

Coincide gives your shell’s startup files 8 seconds, and falls back to zsh if your shell can’t be read. While it reads them, COINCIDE_RESOLVING_ENVIRONMENT=1 is set, so a slow startup file can skip expensive work:

# in ~/.zshrc
[ -n "$COINCIDE_RESOLVING_ENVIRONMENT" ] && return

Put that line after the lines that set PATH, so Coincide still sees it.

An agent isn’t signed in

Coincide uses each tool’s own sign-in. Run the command in the message in Terminal, then click Check Again (or try the message again):

MessageRun
Claude Code is not signed in. Run claude auth login in Terminal, then try again.claude auth login
Codex CLI is not signed in. Run codex login and try again.codex login
Cursor isn’t signed in. Run cursor-agent login in Terminal, then try again.cursor-agent login
Grok CLI is installed but not logged in. Run grok login.grok login
OpenCode lists no models. Run opencode auth login to connect a provider.opencode auth login

Each agent’s page in Settings has a Setup section with these commands and a Run in Terminal button. For extra accounts, see Accounts and API keys.

An agent is too old

  • Codex: “Codex version is too old. Update the Codex CLI to 0.156 or later.” appears below 0.149. From 0.149 to 0.155 Coincide works but says “Update the Codex CLI to 0.156 or later for full support.”
  • OpenCode: “Coincide needs OpenCode 2 or newer. Run opencode upgrade.”
  • Claude Code: “The installed Claude Code is too old for model. Upgrade to vversion or newer to use it.” Only that model is affected; update Claude Code to use it.

Antigravity

Antigravity is set up entirely in Settings › Antigravity: Install Antigravity downloads Google’s runtime, checked against pinned checksums and Google’s signature, and Sign in with Google opens the sign-in in your browser. If you sign in on another device, copy the sign-in link and paste back the address the browser ends on.

  • “Sign in to Antigravity in Settings before you continue.” A turn needed a sign-in; do it in Settings, then send again.
  • “Install Antigravity first, then sign in with Google.” The runtime isn’t installed yet.
  • “Google doesn’t publish an Antigravity runtime for this Mac.” Google’s runtime isn’t available for this Mac.
  • “This Antigravity version can’t sign out. Update Antigravity.” Use Update Antigravity in the same pane.

Before you use it, read the account-risk notice on the Antigravity page.

Opening Coincide the first time

Releases are signed with Developer ID and notarized by Apple, so macOS opens them after the usual “downloaded from the Internet” question. If macOS refuses to open your copy, check it in Terminal:

spctl --assess --type execute -vv /Applications/Coincide.app
codesign --verify --deep --strict -v /Applications/Coincide.app

A release reports accepted and source=Notarized Developer ID. If it doesn’t, delete that copy and download Coincide again from the download page. npx coincide-dev runs these checks for you and installs nothing when one fails.

Updates can only be installed by a verified Developer ID build.Your copy was built from source or isn’t the signed release. Download the release.

Install on Quit installs only after a normal quit, and only when no other copy of Coincide runs. If you reopen Coincide before the confirmation appears, the installer stops; wait for it. Full details in Updating.

Agents stop when Coincide quits

Settings › General › Agents says where agents run. If it shows “Agents run in Coincide”, the reason is under it:

  • “Coincide is turned off under Allow in the Background in Login Items. …” Click Open Login Items… and turn Coincide on.
  • “The agent host didn’t answer. Coincide keeps trying; …” New agents run in the app until the host answers. Quitting and reopening Coincide usually clears it.
  • “This build isn’t signed with a Developer ID, which the agent host needs.” Builds from source run agents in the app.
  • “The agent host is missing from this copy of Coincide. Reinstall Coincide …”

How the host works across quits and updates is in Background agents.

The coincide command

  • “Couldn’t reach Coincide at … Is Coincide running, with Settings › General › Command-line control on?” Open Coincide and check the setting.
  • command not found: coincide in Terminal: Settings › General › Command Line shows where the command is installed, or which folder to add to your PATH.
  • “… already exists and isn’t Coincide’s tool, so it was left alone.” Another program is called coincide in that folder; Coincide won’t replace it.

Every command is in the command-line reference.

Reporting a problem

Use Help › Report an Issue…. It opens GitHub’s bug report form with your Coincide and macOS versions filled in, and nothing is sent until you submit it. If you don’t have a GitHub account, use /bug in the Coincide Discord (Help › Get Help on Discord); reports there also become public GitHub issues. Include the agent and its version, the exact steps and the error text. Never paste API keys, tokens or private code: agent output can contain them. Report security problems privately through GitHub’s private vulnerability reporting.
