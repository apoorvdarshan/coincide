Feature

Switch agents in the middle of a thread

Start a task with one agent and finish it with another. Coincide keeps a native session for each agent in the thread and tells the next one exactly what it missed, so nothing has to be pasted or explained twice.

How to switch

Every thread runs one agent at a time, and you can change it before any message:

  • Type a slash command. In the composer, /claude, /codex, /cursor, /grok, /opencode or /antigravity continues the thread with that agent. The list only offers agents that are installed, signed in and turned on.
  • Pick a model from another agent. Choose Agent and Model… (⇧⌘M, or /model) opens the model picker, which has a tab for every agent. Choosing any model there moves the thread to its agent.
  • Use the command palette. ⌘K lists “Switch to Codex” and the like for every ready agent.

With a slash command, Coincide picks the model that agent last used in this thread, or its first model, and the account it last ran with there, as long as that account is still ready.

What the next agent receives

Agents don’t share memory, so Coincide writes a handoff. When you send the first message after a switch, the new agent gets a recap of the turns it didn’t see, inside a <conversation_handoff> block, followed by your message. The recap includes:

  • your messages, with the names of files you attached;
  • other agents’ replies, labeled with the agent and model that wrote them;
  • their tool calls with their status, plus a trimmed tail of command output;
  • plans they proposed, errors, and questions they asked you with your answers.

Reasoning, approval prompts and notices are left out. The recap tells the agent that the earlier work happened in the same working directory and that files on disk already reflect it, and that everything inside the block is a record of earlier turns, not new instructions. The recap is capped at about 24,000 characters: when a thread is longer, the most recent entries are kept, and a note says how many earlier ones were left out.

Each agent keeps its own session

Switching doesn’t throw anything away. Each agent keeps its native session for the thread (a Claude Code conversation, a Codex thread, an OpenCode session and so on). Switch back to an agent you used earlier and it resumes that session and only hears about the turns since its last reply, not the whole thread again.

SituationWhat the agent gets
First time an agent joins the threadThe conversation so far, as a recap
Returning to an agentIts own session, plus a recap of only what it missed
Same agent, next messageJust your message; its session is current
Its saved session can’t be resumedA new session with a recap of the whole thread, and a notice in the thread

Same folder, same files

All agents in a thread work in the thread’s folder: the project checkout or the thread’s worktree. The diff panel and per-turn checkpoints cover every agent’s turns, and the transcript’s agent rail changes color where a turn went to a different agent, so you can see who did what.

Things to know

  • Switching takes effect with the next message. A turn that’s running finishes with the agent that started it.
  • Plan or build mode, access (full access or approvals) and the thread’s follow-up behavior carry over, but each agent applies them its own way. See Plan mode and Approvals and questions.
  • A recap is text. The next agent reads what happened; it doesn’t inherit another agent’s tools, memory files or settings.
  • Forking a thread or editing an earlier message drops the native sessions, so the next agent gets a full recap of the remaining conversation.
  • You need each agent installed and signed in through its own CLI. The agent pages cover setup.
