Feature

One picker for every agent’s models

Coincide asks each installed agent for its models and puts them in one menu, grouped by agent. Choosing a model also chooses the agent, so switching from Claude Code to Codex is the same gesture as switching between two Claude models.

Opening it

  • Click the model button in the composer, below where you type.
  • Thread › Choose Agent and Model… or ⇧⌘M.
  • Type /model in the composer.
  • In the command palette (⌘K), Choose Agent and Model… searches every model.

What’s in it

The picker has a search field, a Favorites tab and a tab for each agent with its logo. An agent that isn’t set up yet shows a dimmed logo. The chosen tab lists that agent’s models with their context sizes, the agent’s default model marked Default. Searching looks through every ready agent’s models at once. Tab and Shift-Tab step between the tabs, and the arrow keys move through the list.

  • Favorites. Hover over a model and click its star, or use Add to Favorites from its context menu. Favorites from every agent are listed together, and the picker opens on them once you have any.
  • Hidden models. Hide Model in a row’s context menu removes it from the picker. Settings › Models shows hidden models again.
  • Accounts. When an agent has more than one account set up, chips under the tabs choose which account the model runs with. See Accounts and API keys.
  • Reasoning and Speed. Under the list, chips show the current model’s reasoning efforts and, when it offers more than one, its speeds, starting with Standard.
  • Refresh asks the agents for their models again; Agent Settings… opens their settings.

Thread › Reasoning Effort… (⇧⌘E) changes effort without opening the whole picker.

Where the models come from

Coincide doesn’t keep its own list of what you’re allowed to use. Each agent reports its models through its own CLI, with your sign-in, so the picker shows what your plan or key can run. A few built-in entries cover the case where an agent can’t be asked yet.

When Claude Code can’t run a turn at fast speed, for example on a free plan or a model that doesn’t allow it, the thread says why and the turn runs at standard speed.

Managing models in Settings

Settings › Models lists every model from every agent with a filter and a provider menu. From there you can add or remove favorites, hide models or show them again, and add a custom model: enter the ID the agent’s CLI accepts and it appears in the picker even if the CLI doesn’t list it. This helps with a model that’s new or behind a flag.

Settings › General › New Threads sets the model and reasoning effort new threads start with. Choosing a model, effort, speed or access in a thread also makes that the default for the next new thread. A project can override this with its own defaults (see Projects and threads).

Things to know

  • An agent appears in the picker once it’s installed and signed in; until then its tab is dimmed. The agent pages cover setup.
  • Picking a Cursor model in Coincide doesn’t change Cursor CLI’s own default: Coincide puts the CLI’s model setting back.
  • Antigravity’s tab carries a warning about Google’s terms; see Antigravity.
  • The models you can use, and their limits, are set by each provider, not by Coincide.
