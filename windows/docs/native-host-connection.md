# Native host connection and authenticated readiness

Call `ensure_native_host(NativeHostConnectOptions)` only on an initialized MTA worker. Options contain the already pinned physical DataRoot `Scope`, an absolute steady-clock deadline, a shared atomic cancellation flag and a 50–250 ms IPC request timeout (100 ms by default). The helper accepts no executable override, arbitrary arguments, provider input or UI object. Production dispatch is exactly the current native app image with `--background-agent-host <physical DataRoot>`, matching `NativeBackgroundHost`'s entrypoint contract.

The result retains the Scope and exact expected image file identity, typed disposition, last observed ownership, authenticated session summaries, `spawned` and a clear error. `ready()` requires an authenticated `list` response and verified owned scope. An authenticated host containing interrupted/blocked work returns `review` and its summaries; the UI still applies its own per-key adoption and durable receipt policy. A successful connection creates no provider session or account probe.

Ownership is checked before dispatch and again under a per-scope user-only starter mutex. Concurrent normal starters converge on the one host; a starter that discovers an already owned scope authenticates it rather than dispatching again. Owned-but-unreachable and unverifiable scopes never authorize another host or an in-app runtime fallback. Only a free scope can dispatch the fixed native process. The host's existing singleton `HostLease` remains the final cross-process ownership boundary before any provider factory is reachable.

`spawned` records crossing the startup boundary, rather than guaranteeing a child exists: an exception can follow successful `CreateProcess`. Cancellation or deadline expiry after dispatch therefore retains this flag and never kills or automatically resubmits a possibly running host. Root must preserve hosted keys/cursors and review ownership before another action; IPC failure cannot imply absence. Closing the production detached process handle does not stop its host.

Cancellation/deadlines are checked while waiting for the starter and between bounded readiness requests, and again before accepting a response. Existing IPC cancellation has a bounded one-second kernel-settlement allowance beyond the request timeout. Filesystem/process-driver operations themselves are not preemptible; all paths are restricted to local pinned app/data objects. Current image, ordinary single-link PE file and strong ancestor handles are retained during setup. There are no service, startup, registry, power, install or OS changes.

`ensure_native_host_fixture(options, hooks)` is a separate explicit test seam. It resolves both TEMP/base and selected scope through physical directory handles (including DOS 8.3 aliases), then requires an exact owned TEMP scope prefix and synthetic marker before allowing an alternate native fixture image and trusted spawn callback. Tests adapt the fixed production argument request to the existing `BackgroundHostFixture` test route, retain their own child Jobs, and perform only authenticated list readiness. They cover concurrent convergence, physical aliases, owned/unavailable/wrong-image failure, cancellation before/during/after dispatch, failed/lost startup, exact argv and native PE checks. No production host, owner account, provider, model, desktop or network is used.

`Tests/NativeHostConnectionTests.h` exports `native_host_connection_tests(report, exact_background_host_fixture_executable)`. The helper header compiles both as the first runtime include and after `HostIPC.h`, without requiring `NativeHostFactory.h` or changing the caller's Windows JSON macro state. Root owns helper activation, per-provider resolution, conversation reduction, persistence and ACK.
