# Verified native factory for the background host

`NativeHostFactory(options)` is callable as `background_host::Core::Factory`. It reconstructs a normal `AgentLaunch` from the original hosted `Launch` only after validating the trusted provider selection, local paths and saved account binding. It neither starts a background host nor decides whether an existing host can be replaced. Root must retain the separate free/owned/unavailable ownership rule: an unreachable held or unverifiable scope never authorizes an in-app fallback.

Root supplies a host-owned plain-value `resolve(provider, profile_id)` callback. It must read the application's enabled provider preference and account metadata, rather than authorize an executable supplied by the IPC request. It returns `NativeHostProgram{provider, profile_id, executable, profile_directory, cursor}`. Cursor's optional value is `NativeHostCursorProfile{record, cache}`. The resolver must not capture XAML objects or launch a CLI merely while opening a settings panel.

Only Codex/Claude default profiles and a separately verified Cursor profile are eligible. OpenCode, Grok and Antigravity remain refused until their account-continuity contract is supported. The hosted arguments must be exactly the normal `{L"app-server"}` adapter sentinel. Custom commands and test fixture arguments are refused. Codex/Claude keep their existing worker-side account/revision checks before real delivery. Cursor performs an official metadata-only check on host setup and retains the existing fresh account/revision checks on each actual delivery through `make_verified_acp_options`.

The executable must be the exact selected physical native PE file. Ordinary single-link executable/package files and strong project/profile ancestor handles remain pinned for the runtime lifetime. The factory preserves original session, profile, account scope, working directory and instruction strings; it does not rewrite the original hosted Launch or its fingerprint. Saved sessions missing profile/account provenance fail for owner review.

The factory installs a fresh `HostToolContextStore::supplier(thread)` on every launch. Fixed application `tool_descriptions` may follow the current references, and disappear when no grants remain. UI grant references are never frozen in hosted Launch. Existing provider delivery wrapping still leaves stored user input unchanged.

Invoke the factory on the host worker, never on XAML's STA. `options.cancel` is a shared atomic flag used for bounded metadata setup and pre-dispatch cancellation; Root should set it when terminating host setup. `probe` and `make` have production defaults and explicit injectable test seams. Contract tests use only synthetic metadata, copied native fixture binaries and fake sessions; they never run a provider, sign-in, account check or model. Production activation, UI receipt persistence and the packaged helper entrypoint remain Root's integration work.
